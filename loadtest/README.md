# Нагрузочный тест

Проверяет основной сценарий: ребёнок отмечает дело, взрослый подтверждает,
ребёнок видит баланс. Один проход — 6 запросов к API:

1. `GET /api/tasks/my` — дела ребёнка
2. `POST /api/tasks/{id}/mark` — отметка
3. `GET /api/tasks/pending` — очередь взрослого
4. `POST /api/tasks/{id}/confirm` — подтверждение
5. `GET /api/tasks/pending` — обновление очереди
6. `GET /api/balance` — баланс ребёнка

Каждый виртуальный пользователь — отдельная семья. Число семей растёт
ступенями, пока 95-й перцентиль времени ответа не превысит 1 секунду
два окна подряд, не появится больше 1% ошибок или не кончатся семьи.

## Запуск

Окружение из корневого `docker-compose.yml` должно быть поднято,
в `.env` задан `LOAD_PASSWORD`.

```bash
./loadtest/run.sh
```

Скрипт сам готовит семьи (`python -m app.seed_load`), запускает Locust
в контейнере, раз в пару секунд снимает загрузку процессора контейнеров
`backend` и `db` и число запросов, ждущих блокировку в PostgreSQL,
в конце сверяет баланс всех счетов с журналом и печатает сводку.

Параметры через переменные окружения:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LOAD_FAMILIES` | 400 | сколько семей подготовить и сколько пользователей максимум |
| `STEP_USERS` | 20 | сколько семей добавлять на каждой ступени |
| `STEP_SECONDS` | 30 | длительность ступени |

Весь тест должен уложиться в 15 минут: это время жизни access-токена.

## Что смотреть

Результаты складываются в `loadtest/results/`:

- `report.html` — графики RPS, времени ответа и числа пользователей;
- `locust_stats_history.csv` — то же по секундам;
- `cpu.csv` — загрузка процессора `backend` и `db` (100% — одно ядро);
- `locks.csv` — сколько запросов в базе ждали блокировку.

В сводке `summarize.py`:

- на каком RPS и числе семей 95-й перцентиль впервые превысил 1 секунду;
- процессор API и базы в последнюю минуту перед этим;
- миллисекунды процессора API на запрос и процессора базы на запись;
- были ли ожидания блокировок.

Если ответы замедляются при почти полной загрузке процессора API, узкое
место — API. Если больше тратит база или растёт число ожидающих
блокировку, узкое место — база.

Сверка в конце обязана сказать, что баланс всех счетов равен сумме журнала.
Нагрузочные семьи удаляются и создаются заново при каждом запуске
и не трогают демо-семью.
